# Phase 4 — Arena Hub Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**What this plan does (plain words):**

**Desktop (`/arena`, from 1200px).** Your Hub board, built for real:
- **Venue cards:** three cards on a slight 3D arc: CRICKET GROUND, CENTRE COURT and BADMINTON HALL.
  - Each card has its own mini stadium picture: an oval pitch, a tennis court, or a hall.
  - Each card has PLAY (or REMATCH) and SKIP →.
- **Left rail:**
  - the matchday card ("1 OF 3 VENUES" with three bars)
  - the full index, where a page you've opened says **SEEN**
  - the hidden-achievement teaser
- **Facilities row:** TROPHY ROOM, TRAINING ACADEMY, VIEW PLAYER CARD and the volt TEAM UP tile.
- **Top bar:** **YOUR RECORD** (your real wins and losses), QUICK VIEW and sound.
- **Commentary:** the COMM line changes with your progress.
- **Motion:**
  - A card straightens and lifts when you point at it, then tilts toward your cursor (up to 6°).
  - The whole arc sways gently when nothing moves.
  - You can drag to orbit it.
  - Keys **1 2 3** pick a venue.

**Phone.** Your Mobile-Hub board:
- the "TODAY'S FIXTURES · 1 OF 3 PLAYED" header
- three fixture cards (PLAY / SKIP →, or REMATCH / SEE STATS → once played)
- TROPHY ROOM and ACADEMY tiles
- the 5-tab bar at the bottom
- **new:** an **INDEX** button that slides out the same rail as desktop (record, progress, full index, achievements)

**iPad.** The phone layout, centred and a size larger (like the Landing and Intro), with the INDEX drawer.

**Everything reads your saved progress:**
- Played venues, scores, SEEN tags and the record come from the browser's saved match record.
- Returning visitors never see a wrong "UNPLAYED" flash before their record loads.

**Goal:** `/arena` matches `Hub@1440x900` and `Mobile-Hub@390x844` within 2 % (logged deviations masked), and everything shown reflects the saved match record:
- venue states, matchday progress, record, SEEN tags, achievements and commentary
- the hover, tilt, sway and orbit motion and the 1/2/3 shortcuts on desktop
- the fixtures list, tab bar and index drawer on phones and tablets
- axe clean, Lighthouse budget met, `pnpm verify` green

**Architecture:**
- **One pure view builder.** `buildHubView(content, ui, routes, record)` in `src/features/hub/view.ts` turns content, copy and a match-record snapshot into everything the Hub shows (it is unit-tested for every record state). The page components hold no logic and no strings.
- **New generic design-system pieces**, each with stories:
  - scene: `GridFloor`, `VenueArt` (+ an internal `PerspectiveCourt`), `ArenaBackdrop layout="hub"`
  - broadcast: `VenueCard`, `VenueFixture`, `FacilityTile`, `IndexRail`, `RecordChip`
  - primitives: `Drawer`
  - lib: `useOrbit`
- **Shell additions:**
  - `SeenTracker` marks a section seen whenever its page opens (one place, every route).
  - The match record gets a shape guard (`sanitizeRecord`), a readiness hook (`useRecordReady`) and a head flag (`data-record`), so record-bound parts wait for the saved record instead of flashing the fresh state.
- **Same split as Phase 3:**
  - `<Stage from="lg">` holds the 1440×900 board.
  - A feature column holds phones and tablets.
  - Exactly one is displayed by CSS breakpoint, so prerendered HTML never flashes the wrong layout.

**Tech Stack:** React 19, React Router 8 (prerender, `ssr:false`), Tailwind v4 Arena tokens, Zustand persist, GSAP 3 core (lazy via `loadGsap()`), native `<dialog>`, Vitest + Testing Library, Playwright + axe + pixelmatch, Lighthouse.

## Global Constraints

All Phase 0–3 constraints apply:
- **Styling:**
  - Arena tokens only; literal class strings.
  - **No pixel fitting in feature code** (`src/features/styleRules.test.ts` guard).
  - Stage screens place parts at **artboard coordinates** with spacing-scale classes (e.g. `top-26 left-76`), as the Landing does.
  - **Check that no existing type recipe, token, shadow, or Glass edge matches before adding one** (`src/design-system/tokens/catalog.ts` lists them; earlier phases merged duplicates). A new merge that moves a value by more than ~2 % is logged in the spec (Task 7).
  - No raw hex / rgb / cubic-bezier in TS/TSX, no arbitrary type sizes, no inline `var(--color-*)`. GSAP eases come from `src/lib/motion.ts` (`EASE`). ESLint already rejects raw `shadow-[`, `blur-[` and `drop-shadow-[`.
  - Any font override next to a `type-*` class is a **separate `cn()` argument after the type class** (carry-over convention).
- **Accessibility:**
  - Mono ≥ 11 px on screen (A2; the stage floor `--stage-mono-min` holds it inside a scaled stage). Contrast ≥ 4.5:1. Volt focus ring (A3). Targets ≥ 44 px.
  - Nothing invisible is focusable or clickable.
  - Exactly one rendered `<h1>` at every width.
  - Decorative scenes are `aria-hidden`.
- **No visible copy in components or routes.** New strings go in `src/content/ui-copy.ts` under `ui.hub` (plus `ui.routes.arena` which exists). Commentary lines for a visitor win come from `content.commentary.visitorWins`. Design-system components take every word as a prop.
- **Folder rules:**
  - features import shell / design-system / content / lib / assets
  - design-system imports nothing from content / shell / features
  - features never import each other (the Hub is `src/features/hub/`)
- **GSAP:** core only, never imported at module top level, always `await loadGsap()`. Every tween is killed on unmount. No layout reads inside animation loops.
- **Match record:** `useMatchRecord` stays the single source. The Hub never writes to it except through `markSeen` (via `SeenTracker`). Storage key stays `arena:v1`.
- **Never touch** `Yash-Sarda-Resume.pdf`. `player.resumePdf` stays `null`.
- **Lean testing:**
  - unit tests for every pure helper (`buildHubView` states, `sanitizeRecord`, `sectionForPath`, `orbitAngle`, the head flag) and the interactive components (`Drawer`, `IndexRail`)
  - parity stories for both artboards, plus one seeded route parity
  - e2e for record states, drawer, shortcuts, motion guards, viewports
  - no snapshot tests
- **Git and environment:**
  - git 2.15 (no `switch` / `restore`). Branch `phase/4-hub` (already created from `main` at `1c795fe`).
  - Builder commits end with `Co-Authored-By: Claude Sonnet 5.5 <noreply@anthropic.com>`.
  - Ports: tests use 4173 / 6007. **Never kill processes you didn't start**: 6006 and 5173–5176 are Yash's.

## Review Focus

1. **Odd saved records.** For each of these, `/arena` renders a sane state with no crash and no console error, treating whatever is unreadable as a fresh visitor:
   - `arena:v1` missing, blocked storage, malformed JSON, or an object of the wrong shape
   - a played venue with no saved score (status reads `PLAYED`)
   - an unknown venue name, or negative / non-number record values

   Tests: Task 1 unit (`sanitizeRecord`, `buildHubView`), Task 4 e2e (seeded bad storage).
2. **First paint for a returning visitor.**
   - With a saved record, the prerendered page never shows UNPLAYED / 0 OF 3 before the real values. Test: screenshot or DOM check at `domcontentloaded` with the module scripts held back.
   - With JS off, the fresh state shows.
   - With a script error, the parts appear by 3 s.

   Tests: Task 1 unit (head flag), Task 4 e2e (route-held JS, `javaScriptEnabled: false`).
3. **Drag versus click on the arc.**
   - A drag that starts on a card never navigates.
   - A plain click on PLAY still does.
   - Focus by keyboard straightens the card.
   - Leaving the arc mid-drag ends the drag.
   - Resizing across 1200 px mid-sway gives no console errors and leaves no tweens running on unmounted nodes.
   - Reduced motion means no sway (the plate's transform stays at rest).

   Tests: Task 5 unit (`orbitAngle`, hook cleanup) + e2e.
4. **The drawer.**
   - Opening moves focus into it, and Tab cycles inside it.
   - Esc, ✕ and a backdrop tap each close it, with focus back on INDEX.
   - The page behind can't scroll or be clicked while it is open.
   - A link inside navigates and the drawer is gone on the next page.
   - It works at 390×844 and 1024×768.

   Tests: Task 3 unit (`Drawer`) + Task 6 e2e.
5. **Viewport extremes.** Check at 2560×1080, 1440×900, 1366×768, 1280×720, 1200×800, 1199×800, 1024×768, 768×1024, 390×844, 375×667 and 360×640. All of these must hold:
   - no horizontal scroll
   - exactly one rendered `<h1>`
   - rendered mono ≥ 11 px
   - the desktop rail shows every index row and the achievements footer without clipping (with Quick View and Locker Room both listed)
   - the phone tab bar never covers the last tile (the page scrolls)
   - card meta (`VENUE 01` + `PLAYED · 14* NOT OUT`) stays on one line

   Tests: Task 4 + Task 6 e2e loops.

export const VENUES = ["cricket", "tennis", "badminton"] as const;
export type Venue = (typeof VENUES)[number];
export const MATCH_RECORD_KEY = "arena:v1";

const isVenue = (v: unknown): v is Venue => VENUES.includes(v as Venue);
const strings = (v: unknown) => (Array.isArray(v) ? v.filter((s): s is string => typeof s === "string") : []);
const count = (v: unknown) => (typeof v === "number" && Number.isFinite(v) && v > 0 ? Math.floor(v) : 0);

/** Whatever storage held, as a record the site can trust: unreadable parts fall back to a fresh visitor's. */
export function sanitizeRecord(raw: unknown): MatchRecordData {
  if (!raw || typeof raw !== "object" || Array.isArray(raw)) return { ...initial };
  const r = raw as Record<string, unknown>;
  const scores = (r.lastScores && typeof r.lastScores === "object" ? r.lastScores : {}) as Record<string, unknown>;
  const tally = (r.record && typeof r.record === "object" ? r.record : {}) as Record<string, unknown>;
  return {
    venuesPlayed: [...new Set(strings(r.venuesPlayed).filter(isVenue))],

import { useEffect } from "react";
import { useLocation } from "react-router";
import { useMatchRecord } from "./matchRecord";
import { ROUTES } from "./routes";

/** The pages the Hub's index tracks as SEEN (H6). Training Academy is part of the trophies page. */
export const SECTIONS = ["career", "highlights", "attributes", "trophies", "card", "teamUp", "scout", "lockerRoom"] as const;
export type SectionKey = (typeof SECTIONS)[number];

export function sectionForPath(pathname: string): SectionKey | null {
  const path = pathname.length > 1 ? pathname.replace(/\/+$/, "") : pathname;
  return SECTIONS.find((key) => ROUTES[key] === path) ?? null;
}

/** Marks a section seen whenever its page opens, however the visitor got there. Mount once, in the shell. */
export function SeenTracker() {
  const { pathname } = useLocation();
  const markSeen = useMatchRecord((s) => s.markSeen);
  // Wait for the saved record: a mark made before it loads would be overwritten by it (lost on a direct load).
  const ready = useRecordReady();
  useEffect(() => {
    if (!ready) return;
    const key = sectionForPath(pathname);
    if (key) markSeen(key);
  }, [pathname, markSeen, ready]);
  return null;
}
